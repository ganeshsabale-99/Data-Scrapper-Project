# 🚀 Infrastructure & Deployment Guide — Data Scrapper

This guide details the complete **AWS Terraform Infrastructure Provisioning** and **Deployment** setup for **Data Scrapper**:

- **Backend Infrastructure:**
  - **AWS ECR Repository (`data-scrapper`):** Stores container images.
  - **AWS EC2 Instance (`t3.small`):** Ubuntu 22.04 LTS with Docker, Nginx, and an IAM instance role allowing automatic ECR image pulls.
  - **SSH Key Pair:** Uses `gupio-prod-valet-key`.
- **Frontend Infrastructure:**
  - **AWS S3 Bucket (`data-scrapper-frontend-*`):** Stores static React Vite build artifacts.
  - **AWS CloudFront Distribution:** Serves static frontend assets globally with SSL and Origin Access Control (OAC).

## 🏗️ 1. Provision Infrastructure with Terraform

Ensure your AWS CLI credentials are configured (`aws configure`).

```bash
cd terraform

# 1. Initialize Terraform
terraform init

# 2. Preview resources to be created
terraform plan

# 3. Apply and create infrastructure
terraform apply
```

### Outputs Generated by Terraform:
- `ec2_public_ip`
- `ecr_repository_url`
- `s3_bucket_name`
- `cloudfront_distribution_id`
- `cloudfront_domain_name`

## 🌐 2. Deploy Frontend (S3 + CloudFront)

Run from local project root using outputs from `terraform apply`:

```bash
S3_BUCKET="<s3_bucket_name_output>" \
CLOUDFRONT_DIST_ID="<cloudfront_distribution_id_output>" \
AWS_REGION="ap-south-1" \
./scripts/deploy-frontend.sh
```

## 📦 3. Deploy Backend (ECR + EC2)

### Step 3A: Build & Push Docker Image to ECR (Local Machine)

```bash
ECR_REPO="<ecr_repository_url_output>" \
AWS_REGION="ap-south-1" \
./scripts/build-push-api.sh latest
```

### Step 3B: Configure `/home/ubuntu/api.env` on EC2

SSH into your newly created EC2 instance:
```bash
ssh -i /path/to/gupio-prod-valet-key.pem ubuntu@<ec2_public_ip_output>
```

Create `/home/ubuntu/api.env` on EC2:
```bash
cat << 'EOF' > /home/ubuntu/api.env
PORT=3000
NODE_ENV=production
DATABASE_URL="postgresql://user:password@your-neon-db-host/neondb?sslmode=require"
DIRECT_URL="postgresql://user:password@your-neon-db-host/neondb?sslmode=require"
JWT_SECRET="your_secure_jwt_secret"
OTP_SECRET="your_otp_secret"
EXTERNAL_API_KEY_PEPPER="your_key_pepper"
CORS_ORIGIN="https://<cloudfront_domain_name_output>"
FRONTEND_URL="https://<cloudfront_domain_name_output>"
EOF
```

### Step 3C: Trigger EC2 Container Launch & Health Check

Run from local machine root:

```bash
ssh -i /path/to/gupio-prod-valet-key.pem ubuntu@<ec2_public_ip_output> \
  "ECR_REPO=<ecr_repository_url_output> bash -s" \
  < deploy/remote-deploy-api.sh latest
```

## 🛡️ Nginx Reverse Proxy Setup on EC2

On EC2, create `/etc/nginx/sites-available/api`:

```nginx
server {
    listen 80;
    server_name _;

    location / {
        proxy_pass http://127.0.0.1:4000;
        proxy_http_version 1.1;
        proxy_set_header Upgrade $http_upgrade;
        proxy_set_header Connection 'upgrade';
        proxy_set_header Host $host;
        proxy_cache_bypass $http_upgrade;
        proxy_set_header X-Real-IP $remote_addr;
        proxy_set_header X-Forwarded-For $proxy_add_x_forwarded_for;
        proxy_set_header X-Forwarded-Proto $scheme;
    }
}
```

Link and restart Nginx:
```bash
sudo ln -s /etc/nginx/sites-available/api /etc/nginx/sites-enabled/
sudo rm -f /etc/nginx/sites-enabled/default
sudo nginx -t && sudo systemctl restart nginx
```
