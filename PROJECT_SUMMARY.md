# Project Summary — Tech Parks Analyzer (`data-scrapper`)

> Generated by walking the full repo (docs, schema, backend, frontend, in-progress diff) on 2026-09-02.

## 1. What this project actually is

This is **Gupio's internal data-collection/scraping platform**, not a customer-facing product. It:

1. **Scrapes commercial real-estate "venues" across India** from Google Places — Tech Parks, Coworking Spaces, Malls, Hospitals, Stadiums, Airports — city by city, locality by locality.
2. Layers a **lightweight CRM on top** of that scraped data — contact logs, lead ownership/assignment, verification status — so Gupio's sales team can work the list.
3. Scrapes **startup funding news** from 6 sources (Entrackr, VCCircle, TechCrunch, ETStartup, Inc42, YourStory) and runs it through **Gemini AI** to extract founders/investors/round/location.
4. Exposes an **admin web dashboard** (React) and a **partner-facing external API** (API-key auth) for consuming the collected venue data.

> Per `INTERNAL_ISSUES.md` (2026-08-06 correction): *"this is a data collection/scraping tool, not a CRM."* Current priority is scraper reliability and data quality (job durability, concurrency, retry/backoff, validation, dedup) — not CRM features.

## 3. Backend (`apps/analyzer-api`)

**Stack:** Node.js + TypeScript, Express v5, Prisma v6 → PostgreSQL (Neon serverless), JWT + bcrypt auth, Redis (rate limiting/caching), AWS S3 (file storage), Twilio (OTP SMS), Nodemailer (email), Cheerio + Puppeteer (scraping), Google Places + Gemini AI, `node-cron` scheduling, ExcelJS (exports).

### Request flow / mounted routers (`src/app.ts`)
CORS is origin-allowlisted (+ localhost), then: request-context → security headers → rate limiting → JSON body parsing. Routers mounted:

| Prefix | Purpose | Auth |
|---|---|---|
| `/v1`, `/external-integration` | Partner-facing read-only API | `x-api-key` |
| `/auth` | Login/register/OTP/Google OAuth | none |
| `/admin` | Admin user & external-client/key management | JWT |
| `/new-techparks`, `/coworking-spaces`, `/malls`, `/hospitals`, `/stadiums`, `/airports` | CRUD + analytics per venue type | JWT |
| `/contact-logs` | CRM contact history | JWT |
| `/funding-news` | Funding news list + manual scrape trigger | JWT |
| `/media` | S3 upload / presigned URLs | JWT |
| `/rbac` | Roles/permissions | JWT |
| `/export` | Excel/CSV/PDF export | JWT |
| `/city-aliases` | City-normalization alias CRUD | JWT |
| `/national-overview`, `/leads`, `/places-reviews` | Cross-venue dashboards / lead views | JWT |
| `/techparks` | **Deprecated**, returns 410 pointing to `/new-techparks` | JWT |
| `/health`, `/health/live` | Liveness + DB/Redis/SMTP health snapshot | none |

### Scraper engine (`src/libs/venueScraperCore.ts`)
One shared `runVenueScraper()` engine drives all 6 venue-type scrapers (`getAllIndia{TechParks,CoworkingSpaces,Malls,Hospitals,Stadiums,Airports}.ts`):
1. Iterates a hardcoded list of ~25 major Indian cities, each with known localities.
2. For each locality × keyword, does a Google Places **Text Search**, paginating via `next_page_token` (with the required ~2s delay), then repeats at city-level and (for full runs) a final India-wide pass — deduped into one `Map<place_id, …>`.
3. For every unique `place_id`, fetches **Place Details** (address, geometry, phone, website, rating, reviews, photos, business status), then:
   - Rejects non-India results (guards against name collisions, e.g. "Salt Lake" India vs. Salt Lake City, Utah).
   - Rejects placeholder/test rows (`isPlaceholderVenue` — no lat/lng/address).
   - Resolves **City** via `resolveVenueCity`: API value → parsed from formatted address → else logged to `ScrapeReviewQueue` and skipped (never written with a null city).
   - Scores a **parking-problem opportunity** (`HIGH`/`MEDIUM`/`LOW`) by scanning review text for complaint keywords, plus a numeric `parkingPriority` (3/2/1/0) so it sorts correctly (a plain string sorts alphabetically — HIGH, LOW, MEDIUM — not by severity).
   - Computes a `dedupeKey` (normalized name+city) and flags closed listings (`doNotCall`) from Google's `business_status`.
4. A **non-retryable Google error** (bad API key, malformed request) aborts the *entire* scrape immediately instead of retrying the same failure hundreds of times; **transient** errors get exponential backoff + jitter via `googlePlacesClient.ts` (3 retries).
5. Every run is tracked in a DB-backed `ScrapeJob` row (status/counts/who triggered it/timestamps) — replaces old in-memory-only run flags, so a server restart mid-scrape no longer silently loses progress. A `RUNNING` job older than 2h auto-reaps as stale. The weekly `node-cron` scheduler and manual admin triggers share the same per-venue-type lock.

### Funding News pipeline
One generic pipeline (`newsScheduler.ts` + `scrape{Inc42,TechCrunch,Entrackr,VCCircle,ETStartup,YourStory}.ts`) driven by a `SOURCES` array, replacing what used to be 6x copy-pasted per-source logic. Every newly-inserted article is run once through `fundingExtractor.ts` (Gemini, model `gemini-2.0-flash`) to pull founders/investors/round/location/industry — skipped on re-scrapes of articles that already have data, to avoid re-spending quota.

### Company enrichment
`TechParkCompany` (companies discovered inside a tech park) gets nightly sync (`techParkCompanySync.ts`) + auto-enrichment (`CompanyEnrichmentService.ts` / `techParkWebsiteEnrichment.ts`) — website, LinkedIn/Twitter/Facebook/Instagram — matched primarily by Google `place_id` to avoid duplicate/merged companies on re-sync, and tracks `firstSeenAt`/`lastSeenAt`/`isActive` to flag (not delete) companies no longer found on a re-scrape.

### RBAC
Dynamic role/permission system (`AccessRole`, `AccessPermission`, `AccessRolePermission`, `AdminUserAccessRole`) with an in-memory permission cache (`RBAC_PERMISSION_CACHE_TTL_MS`) and a `RBAC_SINGLE_ORGANIZATION_MODE` toggle. `checkPermission([...])` middleware gates admin routes; a `SYSTEM.SUPER_ADMIN` permission gates the most sensitive ones (external API key issuance, etc.).

### City normalization
`CityAlias` table (`alias → canonicalCity`, 294+ seeded entries) collapses scraper suburb/typo variants ("KharadiPune", "Bangalore Division") into canonical city names. `getCityAliasMap()` caches from DB for 5 minutes; invalidate via `POST /city-aliases/invalidate-cache`. New aliases can be added at runtime via `POST /city-aliases` — no code deploy needed.

### External partner API
Documented in full in `EXTERNAL_API_ARCHITECTURE.md`. Separate auth track from the internal JWT API:
- Request flow: `externalApiAuditLogger` (logs every request async, fire-and-forget) → `externalApiKeyAuth` (validates `x-api-key: tpk_<keyId>.<secret>`, HMAC-SHA256 hash compared with `crypto.timingSafeEqual`) → `externalApiRateLimit` (per-key, Redis sliding window with in-memory fallback) → `requireExternalApiScope("<resource>:<action>")`.
- 4 DB models: `ExternalApiClient` (a partner), `ExternalApiKey` (hashed secret, never stored raw), `ExternalApiScope`, `ExternalApiRequestLog` (append-only audit trail).
- Admin issues/revokes keys via `SYSTEM.SUPER_ADMIN`-gated endpoints under `/admin/external/*`; the raw key is shown exactly once at creation.
- Covers all 6 venue types + Coworking (originally Tech Parks only).

### Testing
Vitest-style tests exist for: `hashOtpUtils`, `auth.middleware`, `security.middleware`, `dataScope`, plus integration tests for auth security, the external Tech Park API, and Tech Park CRUD (`src/tests/integration/`).

## 4. Frontend (`apps/analyzer-web`)

**Stack:** React 19 + Vite, React Router v7, TanStack Query v5 + TanStack Table v8, Chart.js, Radix UI + shadcn/ui, Tailwind CSS v4, React Hook Form + Zod, Framer Motion, Sonner toasts.

Route tree (`src/routes/AppRoutes.tsx`) under `/dashboard`, each gated by a permission via `RequirePermission`:
- **Per-venue drill-down** at three levels — National (`national/:state?/:city?`), State (`state/:state?/:city?`), City (`city/:state?/:city?`) — each with a detail view (`.../:id`). The same 3-level pattern repeats for Tech Parks and, separately, Coworking Spaces (`coworking-spaces`, `coworking-spaces/state/:state`, `coworking-spaces/city/:state/:city`, `coworking-spaces/:id`).
- Company detail pages (`company/:companyId`, `coworking-company/:companyId`).
- `leads` (CRM lead list), `funding-news` (+ `:newsId/details`), `recommendations` (AI recs), `client/:clientId` (analytics), `reports`.
- Admin/org management: `users`, `permissions`, `departments`, `roles`, `external-api` (super-admin only).
- `profile`.

Other top-level pages: `Login`, `Register`, `ForgotPassword`, `VerifyOTP`, `LandingPage`, `ProjectOverviewPage`.

Known frontend rough edges (see §6): the sidebar repeats all 6 venue-type links 3x (National/State/City) with no grouping explanation; Users-page search only filters the loaded page; a "Bulk verify in city" button exists end-to-end but is never rendered.

## 5. Database (`packages/db/prisma/schema.prisma`, ~930 lines, 34 models)

Grouped by purpose:

- **Auth/Org:** `AdminUser`, `OtpDispatchLog`, `Organization`, `Department`, `AccessRole`, `AccessPermission`, `AccessRolePermission`, `AdminUserAccessRole`
- **Venues (the core scraped data), one model each:** `NewTechPark` (current, `TechPark` is legacy/kept for history), `CoworkingSpace`, `Mall`, `Hospital`, `Stadium`, `Airport` — each carries address/geo/contact fields, `parking_score` + new `parking_priority` (int), verification/status fields, and (as of today's WIP) `dedupe_key`, `is_possible_duplicate`, `do_not_call`, `spoc_email`
- **Companies inside venues:** `TechParkCompany`, `CoworkingCompany`
- **CRM-lite:** `ContactLog`, `Lead`
- **Content/ops:** `FundingNews`, `ActivityLog`, `ScrapeJob`, `ScrapeReviewQueue` (new)
- **Reference data:** `CityCatalog`, `CityAlias`
- **External API:** `ExternalApiClient`, `ExternalApiKey`, `ExternalApiScope`, `ExternalApiRequestLog`
- **Enums:** `ScrapeJobStatus`, `AdminUserStatus`, `ReviewStatus`, `ActivityAction`, `Status` (contact/lead status), `ContactLogType`, `NewsSource`, `ActivityEntityType`

Neon Postgres (serverless), `DIRECT_URL` used for migrations/Prisma Studio. 19 migrations to date, most recent two (today, uncommitted) add the data-quality fields and parking-priority backfill described below.

- **New:** `src/utils/venueDataQuality.ts` — shared helpers: `isPlaceholderVenue`/`isTestPlaceId`, `extractCityFromAddress` + `resolveVenueCity` (fallback chain), `parkingScoreToPriority`, `isClosedBusinessStatus`, `buildDedupeKey` + `flagPossibleDuplicatesByKey`, `logToReviewQueue`, and contact-status-gated outreach-field guards (SPOC name/phone/email/challenges can't be set while a lead is still `NOT_CONTACTED`).
- **New:** `src/utils/exportValidation.ts` — pre-export gate (`runExportValidation`) checking 100% City non-null, 100% Lat/Lng/Address non-null on real rows, and per-sheet/grand-total row-count reconciliation; a failing result should stop the export rather than silently ship a bad file.
- **New:** `scripts/backfillDataQuality.ts` — one-time cleanup script (per-venue-type) that backfills missing City from address, deactivates placeholder rows, flags closed listings as `do_not_call`, and flags duplicate groups by `dedupe_key`. Run via `pnpm --filter analyzer-api exec tsx scripts/backfillDataQuality.ts`.
- **Modified:** `venueScraperCore.ts` (wires the above into the live scrape path so bad data stops entering at the source, not just at export time), all 6 `getAllIndia*.ts` scrapers, `exportController.ts`, `newTechParkController.ts`, `coworkingSpaceController.ts`, `venueControllerFactory.ts`.

## 7. Known issues (from `INTERNAL_ISSUES.md`, condensed)

### 🔴 Critical
- [x] Google Places key `REQUEST_DENIED` for Malls/Hospitals/Stadiums/Airports — **fixed**, key rotated.
- [x] No lead ownership/assignment — **fixed**, `ownerId`/`assignedAt` + assign/unassign endpoints + UI.
- [x] PDF export vulnerable to HTML/JS injection via unescaped scraped fields — **fixed** (`escapeHtml()`).
- [ ] **No session revocation** — a stolen token or offboarded employee can't be cut off short of rotating the shared session secret (logs everyone out).

### 🟠 High
- [x] No job queue for scrapers (lost progress on restart) — **fixed** via `ScrapeJob`.
- [x] No lock between scheduled and manual scrape triggers — **fixed**, shared per-venue-type lock.
- [x] Zero retry/backoff on scraper HTTP calls — **fixed**, exponential backoff + jitter.
- [ ] No audit log for user approval/rejection or RBAC changes.
- [ ] No executive/team dashboard (cross-venue-type view, funnel, rep activity).
- [ ] No bulk operations anywhere (one row at a time).
- [ ] Users-page search only searches the currently-loaded page.
- [ ] National/state overview stats do a full-table scan + in-app dedup on every load, no caching.
- [ ] Tech Park city-overview pagination is fake (loads the whole city into memory).

### 🟡 Medium (highlights)
- Notifications permission exists with zero actual notification feature.
- `place_id`-only dedup (no fuzzy address/name match) — being addressed by today's WIP dedupe work.
- No field validation on scraped data before write — being addressed by today's WIP.
- Confidence/QA scoring exists for Tech Parks only, not the other 5 venue types.
- AI-extracted funding intel is computed but never surfaced in the Funding News UI.
- Sidebar repeats all 6 venue-type links 3x with no explanation.
- File upload type validation trusts client-supplied Content-Type.
- No pgbouncer/connection pooler configured for Neon.

### 🟢 Low
- Dead "Bulk verify in city" button (wired but never rendered).
- No data history/versioning (re-scrapes overwrite silently).
- No virtualized table rendering (masked by a 100-row API cap).
- Memory-backed rate limiting won't work across multiple instances.
- `$queryRawUnsafe` present in `utils/dbEnums.ts` (not attacker-controlled today, but risky pattern).

### External/infra blockers (not fixable by code alone)
- **Gemini API key has zero quota** — blocks all AI extraction platform-wide until billing is upgraded; the code path itself is verified working and will activate automatically once quota exists.
- **Deployed Funding News scheduler appears stalled** — newest live-DB row was 3+ months stale as of the last check, despite scrapers working fine manually; looks like a deploy/process issue, not a code bug.
- **Google Search scraping is CAPTCHA-blocked** — needs the paid Google Custom Search API, not a code fix.
- Company/tech-park website discovery via DuckDuckGo/Bing scraping has the same CAPTCHA/blocking problem.

## 8. Running it locally

```bash
pnpm install
pnpm --filter @repo/db exec prisma generate
pnpm --filter @repo/db exec prisma migrate deploy
pnpm dev                          # API + Web together (Turborepo)
pnpm --filter analyzer-api dev    # API only — :4000
pnpm --filter analyzer-web dev    # Web only — :5173
pnpm --filter @repo/db exec prisma studio   # DB browser
```

Env vars are split across `packages/db/.env` (DB connection + seed super-admin) and `apps/analyzer-api/.env` (server, auth secrets, SMTP, Twilio, AWS S3, Redis, Google APIs, Gemini key, RBAC config) — see `PROJECT_CONTEXT.md` for the full annotated list (values are not reproduced here since it's git-ignored / contains secrets).
